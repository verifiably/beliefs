# Overlapping publications implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, inline; the user chose native inline execution at plan review (round 3, `5875060`) because Tasks 2 to 5 share the world read view, the capture types and one conformance declaration. Steps use checkbox (`- [ ]`) syntax for tracking. Every task ends with passing completion checks (`just test-fast` green, `tasks check` clean); a fresh whole-branch reviewer and corrective re-reviews follow Task 7.

**Goal:** Let a world hold one address in several live corpora when the copies have equal content, read it once everywhere, decide acceptance and attribution over the holder set, and fold correction standing once, while differing content, uid corruption and ambiguous provenance still refuse.

**Architecture:** The address map becomes multi-holder keyed by a content identity the kernel already computes; every world read labels a record by its least present holder and reads the holder set wherever the answer depends on it. Correction standing moves into a successor `retraction-enumeration` rule over a versioned rule input, with v1 untouched. Publish attributes a multi-holder record by own-holder, agreement, then the earliest origin in the held supersession order.

**Tech Stack:** Python 3.11+, pytest, the existing durable fixtures (two worlds, publish → adopt), the rules store, N2 and the acceptance runner. No dependency, permit, contract-release, world-config or TypeScript change.

**Spec:** `docs/superpowers/specs/2026-10-28-overlapping-publications-design.md`, accepted at `e14315c` (revision 10; the acceptance stamp is `5f28d5a`). Read the spec first; this plan cites it by section and repeats no ruling it already makes. **Revision 4** of this plan: revision 2 (`1ab68bf`), after the round-1 review of `555c85b`, merged Tasks 2 and 3, split Task 4 and set the accounting to `(33, 33, 6)`; revision 3 (`5875060`), after the round-2 review, moved the ride-along to the live table as spec §9 says, added J20-b in its place, and fixed the helper signatures and three sabotage sites; this revision, after the user's round-3 review of `5875060` (`codex/gpt-6-astra`), retargets historical arms inside the task that falsifies them so every task's completion checks pass, keeps the binding helpers on v1 until Task 4 switches them, gives G14-c a decisive outcome assertion, and makes the removal regression the raw-written malformed-fixture case.
