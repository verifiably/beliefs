## 2. New findings

### Important

**I-A. The skip-reason comparison has no baseline data.** (Durable coverage evidence, "Hosted acceptance" 4th bullet; step 2) Acceptance requires non-capability hosted skips to "match, by reason, the skips in the step-2 local baseline." Step 2 runs plain `just test` and "records its test counts and failures." `addopts = "-q --ignore=tests/acceptance"` leaves pytest's default `-r fE`, so skip reasons are never printed; local commands "keep their current flags," so no JUnit is written; tt records counts only. Failure: at acceptance there is nothing to compare against, and the implementer either guesses or reruns the full suite off-plan. Fix: have step 2 capture skip reasons without changing any command string — e.g. run the baseline with `PYTEST_ADDOPTS=-rs` (the summary line tt counts is unaffected) and record the SKIPPED lines for both phases — or define the expected non-capability reasons from the explicit skip sites (seven call sites across six modules: `test_arm_staleness`, `test_composite`, `test_frozen_guards`, the three `root reads mode-0` modules, `test_world_read`).

**I-B. The post-activation verification the task requires is missing.** (Verification and activation sequence, steps 7–8) The task body: "After approved activation, commit .tt.toml … verify focused execution/recorded skip/forced failure/covered remote push." Shared plan Task 7 says the same, and the ops pilot did it (its activation note: the covered push's hook recorded `test-fast skipped by policy`, plus a separate registered-main run confirming its own `.tt.toml` validates and skips). The spec's steps 7–8 only inspect the activation push's hosted forced run. Failure: activation can close without `.tt.toml` ever confirmed valid on the registered main checkout, and without confirming that `test-one` still records `ran` and a broad target records a `skipped` row with null `exit`/`tests`/`selection`/`slowest`. Fix: add a post-activation check from registered main — `just test-one <one small path>` records `execution: ran`; the activation push's hooks recorded `check-code` and `test-push` skipped with null outcomes (read from the shared log); step 3's forced-failure fixture (test-full propagating failure) passes via `test-one`; the activation push's hosted run meets the same acceptance criteria — each recorded on beliefs-067a8d.

**I-C. The prescribed activation commit leaves guide claims stale.** (Pre-push coverage routing; steps 4 and 7) AGENTS.md Gates currently says "CI carries the complete package suites for pushes to `origin/main` (`ci_suite_refs := "refs/heads/main"`); every other push keeps the complete local gate," and the justfile header and the comment above `ci_suite_refs` say the same. Step 4 updates guides while policy is enabled and refs are `main`; step 7's activation commit is "`.tt.toml` and the `ci_suite_refs` widening." The repository rule: "Correct stale current-facing claims in the same change that makes them stale." Failure: either step-4 text describes policy-off/all-branch coverage before either is true, or post-activation AGENTS.md tells agents feature pushes still get the full local gate when they get only hygiene — and agents use that text to decide when to force. Fix: say that step 4 writes guides for the pre-activation state (or state-independently: "policy is whatever `.tt.toml` says; covered refs are `ci_suite_refs`"), and that the activation commit also updates every guide/comment line stating policy state or covered refs. Add the same line to rollback.

### Minor

1. Stale shared-design revision (Intent and authority). The spec cites ops design revision `1ce9abe`. The current approved text is `469140a`, which carries the user's 2026-10-29 billing amendment (record allowance when available; exact balance not a prerequisite; no-paid-overage unchanged). The beliefs billing handling is consistent with it; cite `469140a`.
2. M5 scope (Pre-push coverage routing). The template's warning block runs on every full-route push regardless of policy. It evaluates `just --evaluate tt` → `python3 tools/tt` and loads `tools/tt` relative to cwd. In `hook_repo` that is `FileNotFoundError` (an `OSError`), so the hook exits 2 — every full-route routing case (`feature`, `main`+`feature`, `backup`, empty refs) fails under `check=True`, not only the policy-off warning case. Say that the shared `hook_repo` fixture copies `tools/tt`, and only the warning case adds a `.tt.toml`.
3. What the coverage contract test means by "matched". The hook matches with `fnmatch`, where `*` crosses `/`; GitHub's `*` does not, only `**` does. A naive `fnmatch(stripped_glob, pattern)` would accept `refs/heads/*` against `branches: ["*"]`, which does not cover `feature/x`. The exact trigger pin in step 3 mitigates this, but state the relation: glob `refs/heads/*` requires `**`; `refs/heads/<name>` requires `<name>` or `**`.
4. Hosted env leakage into front-door tests. The workflow now sets `TT_FORCE=1` at job scope, and runners set `GITHUB_ACTIONS=true`. Any front-door subprocess that inherits the environment runs forced on hosted, so skip/warning cases fail only in CI. Step 3 says rebuild "fixtures" key by key, but `test_one_preserves_arguments_and_records_the_run` builds `{**os.environ, …}` inline, and its `empty` call inherits — neither is a fixture. Say "every subprocess in the file" and name `TT_FORCE`/`GITHUB_ACTIONS` as required-absent unless a case sets them.
5. Failure short-circuit and marker children. Shared Task 4 pins "genuine failures stop later steps" with marker commands for children. Step 3's proof list covers `test-full` failure propagation but not the hooks: a failing hygiene step must stop `check-code`, and a failing `check-code` must stop `test`/`test-push`. Add those, and say real recipes are exercised with `just --set` marker commands — real children would run suites inside the suite, and `check-hygiene`'s `tasks check` fails on runners (no `tasks`).
6. `broad_targets` names are unchecked. `read_policy` validates only the protected set, so a typo in `.tt.toml` (`test_push`) silently leaves that target running by default. A one-line contract test that every `broad_targets` entry is a tt target name in the justfile closes this.
7. Unnamed stopping route. The certified-host section lists three stopping routes; `hook-pre-push` (the full route for feature pushes and other remotes) also runs capability tests today. It had 0 runs in October, so the gap size stands, but the list should name it since it stops too.
